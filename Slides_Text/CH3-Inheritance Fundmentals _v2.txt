3Inheritance is a fundamental object -oriented technique 
used to create reusable classes.
It allows a programmer to create a new class based on 
an existing class.
The existing class is called the superclass (parent / base 
class): the class being inherited from .
The new class is called the subclass (child / derived 
class): the class that inherits from another class .
The subclass inherits accessible fields and methods 
from the superclass.


--- Page 4 ---
4Code reuse: Put common fields/methods in the superclass and reuse 
them in subclasses (avoid duplicate code).
Specialization : Create a more specific class by adding new members or 
overriding inherited methods.
Easier maintenance: Changes in the superclass automatically apply to all subclasses, making updates faster and consistent.

--- Page 5 ---
5 Inheritance Represents an "is-a" Relationship
Each object of a subclass is also an object of its superclass.
Examples ：
 A Student is a Person.
A Car is a Vehicle.
 Java supports only single inheritance
each class is derived from exactly one direct superclass.

6In UML class diagrams, inheritance is represented by:
A solid line with a hollow triangle arrow pointing to the parent 
class.
The arrow always points from the child to the parent.
What Does a Subclass Inherit?
public and protected members of the superclass.
A subclass cannot directly access private fields of the superclass.
Private data should be accessed using getter and setter methods.

Constructors are NOT inherited.
When you create a child object, Java must build the parent part first.
If you don ’t write super , Java automatically inserts super() as the first line in the 
child constructor.
super(...) must be the first statement in the constructor.
If the parent does not have a no -arg constructor Parent(), then the child must 
explicitly call one of the parent ’s constructors using super(parameters).

Constructor Chaining
18 A constructor can call another constructor using super(...) or this(...).
This creates a constructor call chain , where constructors are executed 
from superclass to subclass.
The constructor call must be the first statement.
The chain always ends with the Object class constructor.

Overriding Methods
21A subclass inherits methods from a superclass.
 Sometimes it is necessary for the subclass to 
modify the implementation of a method 
defined in the superclass. This is referred to as method overriding . 
Overriding requires the same method 
signature (same name + same parameters).
Use @Override to ensure you are really 
overriding a parent method.

Why we use @Override annotation
@Override tells the compiler that this method must override  a method from the 
parent class.
If the method does not correctly override a parent method (wrong name or 
parameters),
the compiler will generate an error .
Without @Override , a mistake may cause the method to be treated as a new 
method ,
and no compile- time error will appear .
Although @Override is not required, it is strongly recommended because it helps 
prevent errors .

  Good practice:
From now on, you MUST use @Override when overriding methods. 23

The toString() Method in Object
30The toString () method returns a string representation of an 
object.
When you print an object: 
 System.out.println(obj);
Java automatically calls: 
       obj.toString ()  at run time
Default output looks like:
 ClassName @hashCode
The default output is not very informative.
Therefore, we usually override toString () in our classes


--- Page 31 ---
31Override toString() to print meaningful information.
Use @Override to avoid mistakes.
