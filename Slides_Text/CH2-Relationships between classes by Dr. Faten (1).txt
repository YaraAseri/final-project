Why Do We Use UML to Model Relationships
▪UML is used to visualize and document the structure 
of a software system.
▪Real-world software systems consist of  multiple 
interacting classes.
▪UML class diagrams allow us to clearly specify how 
classes are connected.
▪Defined UML symbols help avoid ambiguity when 
describing class relationships.

Relationships Between Classes
UML class diagrams can represent different types of relationships between classes:
➢Association
▪A general relationship showing that objects of  two classes are connected or interact.
➢Aggregation
▪A has -a relationship where the part can exist independently of  the whole.
➢Composition
▪A stronger has -a relationship where the part is an essential component of  the whole.
5


--- Page 6 ---
Association Relationship
▪An association represents a relationship between objects of  two or more classes.
▪It is the most general type of  relationship in UML.
▪An association does not imply ownership or strong dependency.
▪Objects involved in an association can exist independently.
▪A specific instance of an association is called a link.
▪Associations are often used to represent interaction or communication between objects.
▪Associations are sometimes referred to as use relationships

Aggregation Relationship
8➢Aggregation represents a has -a relationship between classes.
➢It is a special form of  association.
➢The part can exist independently of  the whole ( The whole and the part have separate 
lifecycles ).
➢The relationship does not imply strong ownership.
➢UML Representation
▪Aggregation is represented by an empty diamond ( ◇).
▪The diamond is placed at the whole  side of the relationship.


--- Page 9 ---
Aggregation Example
9Example: Student – Address:
➢A Student  has an Address .
➢An Address  can exist independently of  a Student.
➢The same Address may be shared by more than one Student.
▪Multiplicity:
➢One student → one address
➢One address → zero or more students


--- Page 10 ---
Composition Relationship
10➢Composition represents a strong has -a relationship between classes.
➢It is a stronger form of aggregation.
➢The part cannot exist independently of the whole (The whole owns the part)
➢If the whole object is destroyed, the part is destroyed as well.
➢UML Representation
▪Composition is represented by a filled diamond ( ◆).
▪The diamond is placed at the whole  side of the relationship.


--- Page 11 ---
Composition EXAMPLE
11Example: Student – Name
➢A Student  has a Name .
➢The Name  object is an essential part of  the Student.
➢The Name cannot exist  without the Student.
▪Multiplicity : One Student → one Name

Implementing Has -a Relationships In Java
12▪A has-a relationship is implemented using instance variables  (object references).
▪The “whole” class contains a field whose type is the “part” class.
Note:
❖The Name  class is defined separately.
❖ The Student  class uses it through an instance variable (has -a).

CREATING PART OBJECTS (COMPOSITION)
▪Creating the Part Object in the Constructor
▪In composition, the whole object creates its part object.
▪The part is usually created inside the constructor of  the whole.

ACCESSING DATA FROM THE PART OBJECT
Accessing Part Data (Getter Methods)
▪The whole class can access the part’s data using getter methods.
▪This keeps data fields private and follows encapsulation.
▪Since name is the part object, its methods can only be accessed using the variable name, not 
directly.
